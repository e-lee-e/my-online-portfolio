TwoMillion

Une reconstitution de l'ancienne plateforme HackTheBox, avec son code d'invitation cassable. Tout le début se joue dans le JavaScript de la page, avant même d'avoir un compte.

La chaîne en cinq lignes

Le résumé avant le détail, pour que quelqu'un qui ne fera pas la machine comprenne quand même de quoi il s'agit.

  • Un JavaScript obfusqué côté client, qui cache la logique de génération du code d'invitation
  • Une API dont les points d'entrée se laissent énumérer une fois le compte créé
  • Un point d'entrée qui permet de passer son propre compte en administrateur
  • Une injection de commande dans la génération de VPN côté administration
  • Un fichier .env avec des identifiants réutilisés, puis un noyau obsolète et CVE-2023-0386

Reconnaissance

Le site reproduit l'ancienne page d'inscription de HackTheBox, protégée par un code d'invitation. Sans ce code, impossible de créer un compte par le formulaire classique.

Le code d'invitation

Le JavaScript livré au client contient la logique complète de génération du code : l'endpoint /api/v1/invite/how/to/generate explique la marche à suivre, qui repose sur un chiffrement par substitution réversible (ROT13) suivi d'un encodage Base64. En rejouant l'algorithme dans l'autre sens côté client, on génère soi-même un code d'inscription valide, sans jamais avoir eu d'invitation légitime.

Tout algorithme exécuté côté client est lisible et rejouable par l'utilisateur : ce n'est jamais un mécanisme de contrôle d'accès.

Énumération de l'API

Une fois le compte créé, l'énumération des routes de l'API révèle un défaut de contrôle d'accès sur l'endpoint de mise à jour des paramètres, /api/v1/admin/settings/update : rien n'empêche un compte non privilégié de modifier lui-même son propre attribut is_admin.

Passage administrateur puis shell

Une fois administrateur, la fonctionnalité de génération de profil VPN devient accessible. Elle concatène directement les entrées utilisateur dans un appel système (shell_exec côté PHP), ce qui ouvre la voie à une injection de commande et à l'exécution de code arbitraire sous l'identité www-data. 

# Preuve de concept de l'injection applicative
1. Élévation vers is_admin=true via l'API de mise à jour des paramètres
2. Concaténation de commande détectée dans l'export de configuration VPN
3. Exécution de commandes système, accès confirmé en www-data

Élévation de privilèges

Le fichier de configuration .env expose les identifiants de la base de données, réutilisés par le compte système admin. Sur cette machine, le noyau Linux (5.15.70, sous Ubuntu Jammy) est vulnérable à CVE-2023-0386, un défaut dans l'implémentation d'OverlayFS/FUSE qui permet à un utilisateur local de se créer un exécutable avec les attributs SUID et d'obtenir un shell root. 

# Constat d'audit sur l'élévation de privilèges noyau
→ Vulnérabilité : CVE-2023-0386 (OverlayFS/FUSE)
→ Mécanisme : exécutable SUID créé via l'arborescence FUSE
→ Résultat : élévation complète vers UID 0

Ce que j'en retiens

TwoMillion enchaîne trois défauts de conception très différents : une logique de sécurité déplacée côté client, un contrôle d'accès absent sur une route d'administration, et une injection de commande dans un appel système. Les correctifs : bannir toute concaténation de données utilisateur dans un appel système, verrouiller le contrôle d'accès de l'API pour interdire l'auto-promotion via is_admin, et appliquer sans délai les correctifs noyau contre CVE-2023-0386.
